# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this repo is

Docusaurus documentation site for the ERC-7730 clear signing ecosystem (registry CI, PR review guidelines, descriptor authoring, wallet integration). Docs-only mode: the `docs/` folder is served at the site root (`routeBasePath: "/"`), there is no blog and no custom landing page. Intended to be hosted under a clearsigning.org subdomain (`url` in `docusaurus.config.ts` is `https://docs.clearsigning.org`).

## Commands

```bash
npm install
npm start          # dev server with hot reload
npm run build      # production build into build/ — run this to validate changes
npm run serve      # preview the production build
npm run typecheck  # TypeScript check of the config/theme code
```

There are no tests; a clean `npm run build` is the validation bar. The build fails on broken internal links (`onBrokenLinks: "throw"`) and warns on broken anchors — fix both.

## Things to know before editing

- **Two pages fetch their content in the browser, not at build time**: `docs/wallets/typescript-sdk.mdx` (renders `GUIDE.md` from [sourcifyeth/clear-signing](https://github.com/sourcifyeth/clear-signing)) and `docs/auditors/auditor-guide.mdx` (renders `auditors/README.md` from the registry). Both use the `RemoteMarkdown` component (`src/components/RemoteMarkdown.tsx`), which fetches from raw.githubusercontent.com on page load, shows a spinner meanwhile, rewrites repo-relative links, and strips the document's own `#` title. Their content never appears in the build output — to change it, change the source repos. Consequences: the build does not validate those documents' links, and the pages have no table of contents.
- Sidebar is autogenerated from the `docs/` folder structure: `_category_.json` files set section labels/order, `sidebar_position` frontmatter orders pages within a section.
- Mermaid diagrams are enabled (`@docusaurus/theme-mermaid`); use fenced ```mermaid blocks. They render client-side, so a successful build does not prove a diagram renders — check syntax carefully when editing one.
- Docs content is based on the real behavior of the [registry](https://github.com/ethereum/clear-signing-erc7730-registry) CI workflows and the [python-erc7730](https://github.com/LedgerHQ/python-erc7730) v2 linter. When those repos change, the CI checks page (`docs/registry/ci-checks.md`) is the most likely page to go stale — verify claims against the workflow files before editing.
- Admonitions need the Docusaurus v3 bracket title syntax: `:::info[Title]`, not `:::info Title` — the latter renders literally.

## Design

- The styling deliberately mirrors **clearsigning.org**: Geist / Geist Mono fonts (bundled in `static/fonts/`), its accent blue palette and light/dark surface colors (`src/css/custom.css`), and its favicon (`static/img/favicon.svg`, also used as the navbar logo). When changing the design, take clearsigning.org as the reference; keep both themes working.
- Mermaid diagram colors come from `themeConfig.mermaid.options.themeVariables` in `docusaurus.config.ts`. The same variables apply to light **and** dark mode — nodes intentionally render as light "cards" on the dark background, so pick colors that work on both.
- Diagram sizing: `.docusaurus-mermaid-container` CSS gives SVGs a min-width with horizontal scrolling. Author flowcharts narrow (roughly two columns of subgraphs max) or they become unreadable.

## Content policies

- The registry's AI analyzer workflow (`analyze.yml`) is deliberately **not** documented — don't re-add it.
- The docs state that **wallets must only use attested descriptors** — keep new content consistent with that stance.

## Git conventions

- Commits are authored as `manuelwedler <manuel@wedler.dev>` (set in the repo git config). Do not add `Co-Authored-By` or `Claude-Session` trailers to commit messages.
- When a request contains a list of separate items, make **one commit per item**, each scoped to only that item's changes.
